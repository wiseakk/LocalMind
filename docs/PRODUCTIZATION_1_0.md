# LocalMind 1.0: сборка и проверка продукта

Это кандидат выпуска, **не принятый Windows-продукт**. Автоматические проверки,
реальный CPU inference и загрузка GGUF не заменяют установку на чистой Windows,
живой микрофон, прослушивание, визуальную проверку и реальное оборудование HA.
Текущие результаты и блокеры записаны в `STATUS.md`.

## Пользовательский запуск

Запустить `LocalMind-1.0.0-rc2-Setup.exe`, затем ярлык **LocalMind**. Python, venv,
pip и терминал пользователю не нужны. Компонент Ollama предлагается установщиком;
существующий Ollama обнаруживается. Для распакованного комплекта одна команда:

```powershell
.\dist\rc2\LocalMind\LocalMind.exe
```

В мастере нажать «Подготовить распознавание», дождаться готовности в «Загрузках»,
затем «Подготовить озвучку». Основные ресурсы: multilingual small и Silero xenia.
Мастер готовит выбранный профиль: быстрый small или качественный medium.
Balanced совместим с small. Base не поддерживается; старые файлы не удаляются.
Мастер проверяет контрольные суммы и пробный CPU inference. Ресурсы загружаются
только по явной кнопке; обычные STT/TTS используют локальные файлы.
Silero v5.6 ru: CC-BY-NC-SA-4.0; источники и SHA-256 — в `config/voice_resources.json`.

Установить нейросеть из каталога либо импортировать GGUF из офлайн-комплекта,
затем отдельно нажать **«Проверить и выбрать»**. Установка не активирует модель.
Работающий выбор Gemma не заменяется. Имена фактически использованной модели
берутся из Ollama, а не придумываются интерфейсом.

Модели, состояние загрузок, активная LLM, журнал и профиль интерфейса находятся
в `%LOCALAPPDATA%\LocalMind`. Файлы установки отдельно в
`%LOCALAPPDATA%\Programs\LocalMind`. Удаление программы сохраняет пользовательские
модели/настройки. Старые `.env`, `results/private/active-model.json` и `models`
из прежнего каталога приложения копируются повторяемо, без удаления источника.
Разрешения и HA-токен из старого `.env` автоматически не переносятся.
Автоматического поиска другого checkout или прежнего браузерного профиля нет;
перенос истории и произвольных прежних UI-настроек пока не реализован.

## Для сборщика, а не пользователя

Нужны Python 3.11 x64, .NET Framework C# compiler и Inno Setup 6.7.x.
Скрипт скачивает официальный embedded CPython 3.11.9 и wheel-зависимости в
приватный runtime; разработческий venv не копируется. Подпись официального
OllamaSetup проверяется до упаковки. Сборка ничего не публикует.

Онлайн-вариант (голос/LLM скачиваются мастером):

```powershell
python scripts/build_windows.py
```

Отдельный офлайн-вариант, из заранее подготовленных и проверенных ресурсов:

```powershell
python scripts/build_windows.py --offline-assets PATH_TO_PREPARED_MODELS --offline-gguf PATH_TO_REVIEWED_MODEL.gguf --offline-license apache-2.0
```

`--iscc PATH_TO_ISCC.exe` задаёт расположение компилятора. `--resume` продолжает
проверку/упаковку существующего `dist/LocalMind` после сбоя, повторно копирует
текущие исходники, проверяет подпись Ollama и запускает smoke import приватного
runtime. Для нового чистого варианта используйте новый checkout; скрипт не
удаляет старые сборки. Офлайн-вариант выводится в `LocalMind-1.0.0-rc2-Setup.exe`.
Офлайн GGUF загружается локальному Ollama через blobs/create, затем проверяется
tags/show; модель называется `localmind-offline:1.0` и активируется только отдельно.

В комплекте обязателен GUI smoke и пробный запуск workers из приватного runtime.
Сборка EXE сама по себе не доказывает установку/удаление на чистой машине.

## Офлайн-демо после настройки

1. Дождаться готовности ASR, Silero xenia и выбранной LLM; сохранить выбор.
2. Отключить сеть обычным пользовательским способом, перезапустить LocalMind.
3. Отправить «Что такое RSA?» текстом; убедиться в содержательном ответе.
4. Записать «Как сварить пельмени?», проверить исходную расшифровку, исправить
   при необходимости и отправить. Должна звучать xenia, без скрытой загрузки.
5. «Включи настольную лампу» должно явно показать **DEMO / симуляция**, если
   контроллер не подключён. Реальный HA не требуется для запуска приложения.

## Восстановление и границы

- Нет зависимостей/несовместимая DLL: повторить установку LocalMind. Пользователю
  не предлагается pip. Отсутствующие/повреждённые модели: кнопка подготовки.
- GPU недоступен: выбрать Balanced/CPU. Наличие RTX не доказывает наличие CUDA
  DLL. Совместная нагрузка Gemma/STT на GPU требует отдельного опыта.
- Ollama не отвечает: запустить установленный Ollama, повторить проверку мастера;
  при отсутствии — повторить установку с компонентом локального движка.
- Ошибки поиска/metadata/pull сохраняются с этапом в экспертной диагностике
  загрузок; токены, URL с credentials и пути удаляются из технических сообщений.
- HA принимает локальный числовой IP, без редиректов и proxy. `.local` DNS-имена
  сейчас не поддержаны. Токен защищён DPAPI текущего пользователя; при переносе
  на другую учётную запись контроллер подключается заново.
- Управление браузером ограничено объявленной закладкой; системные настройки —
  открытием страниц Экран/Звук в расширенном режиме. Произвольного управления
  вкладками и изменения настроек ОС пока нет. Рабочее пространство «Учёба» —
  фиксированный набор Блокнот/Калькулятор. Мутации каталогов не реализованы.
- Удаление/перезапись файлов требуют точного подтверждения, но автоматического
  отката пока нет. Документы с несохранёнными изменениями автоматически не закрываются.
- При рестарте запросы действий не повторяются автоматически. HTTP-кэш request_id
  ограничен текущим процессом; UI отвергает старую server_instance. Это не
  транзакционная гарантия exactly-once между падениями процессов.

## Git в ограниченном worktree

Git metadata находится в основном checkout вне доступного каталога. Попытка
создать `index.lock` вернула Permission denied. Коммиты здесь не созданы.
Промежуточные снимки сохранены в `.test-artifacts/milestones`, окончательный код
сохраняется в этом worktree. Ранние снимки — рабочие, не принятые релизы.

Владелец orchestrator должен сохранить этот worktree, создать разрешённый
изолированный checkout и перенести изменения по пяти этапам: установка/голос,
загрузки, UX, desktop, HA. Общие файлы (`server.py`, HTML, registry, tests)
разделять по hunks через `git add -p`, новые файлы добавлять явным списком.
Перед каждым `git commit` выполнить полный набор из архитектурного контракта,
проверить staged diff и реальные обязательные сценарии. Не выполнять `git add .`,
не обходить ACL и не объявлять пять коммитов существующими. Слияние/публикация
этим изменением не выполняются.
