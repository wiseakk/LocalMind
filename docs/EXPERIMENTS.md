# Проверки и план измерений

Дата этого инженерного прогона: 28.10.2026. Реальные аппаратные измерения отделены
от автоматических проверок. Финальные команды и совокупные числа находятся в
`docs/STATUS.md`, который обновляется после интеграции.

## Что действительно проверялось

Голосовой набор: `python -m pytest -q tests/test_voice.py` — **17 passed**,
один warning кеша pytest в ограниченной Windows-среде. Реально использовались
установленный PyAV 18.1.0 и дочерний Python-процесс: декодирование синтетической
WAV, тишина, повреждённый файл, превышение 30 секунд, отказ распознавания тишины
и запрет playlist под видом WAV. Проверены лимиты, cleanup, занятость, таймаут,
неверный JSON worker и отсутствие активов.

CUDA fallback проверен mock-моделью, а unit-тест Piper WAV — mock-движком.
Отдельный реальный synthetic smoke описан ниже. WER/CER по человеческим записям,
RAM/VRAM и качество микрофона не измерялись. Синусоида в unit-тесте не является
образцом русской речи.

Совокупный интеграционный прогон на момент подготовки этого документа:
**121 passed, 1 warning, 35 subtests passed in 2.31s**. Более поздние проверки могут увеличить набор;
актуальный результат сверяется со STATUS. Запуск CUA не обнаружил браузер, а
Playwright не смог запустить дочернюю установку браузера (EPERM). Скриншоты,
проверка zoom и keyboard в реальном браузере этим прогоном не подтверждены.

## Реальный синтетический voice smoke

Pip `install --target .voice-deps piper-tts` не смог записать приватный временный
каталог из-за ACL restricted-token среды. Для проверки движка официальные wheel
Piper **1.8.0 Windows amd64** и pathvalidate **3.3.1** загружены из PyPI,
проверены по SHA-256 PyPI metadata и распакованы только в `.voice-deps`.
Существующее внешнее окружение не изменялось. Установленный onnxruntime
использовался из provisioned environment. Команды `setup-tts` и `setup-stt`
загрузили Denis, base и small в `models`. Кеши setup теперь явно ограничены
`models/.download-cache`; исходная попытка записи HF ref/log вне проекта была
отклонена sandbox, после исправления setup повторён успешно.

С `PYTHONPATH=.voice-deps`, `HF_HUB_OFFLINE=1` и отключённой HF-телеметрией
вызван непосредственный внутренний worker на **синтетическом**, заранее известном
тексте «Включи настольную лампу.». Он создал WAV **1.474 сек**, время TTS **3244 мс**.
Это реальный Piper inference, но прослушивание человеком и browser playback не проверены.

| Реальная CPU-модель, исходная подсказка словаря | Полученная расшифровка | Время worker |
|---|---|---:|
| base/int8 | «Клечи на стольную лампу.» | 708 мс |
| small/int8 | «Ключим на стольную лампу.» | 1835 мс |

Ошибки не исправлялись скрытой заменой текста. Временное добавление точной
команды в prompt дало правильную фразу на том же образце (base 756 мс,
small 1825 мс), но этот вариант **отброшен**: образец совпал с подсказкой, что
не доказывает обобщения. В финальном коде осталась исходная подсказка словаря.
Дополнение сигнала тишиной по 0.2 сек также проверено: base дал «Кричи на
стольную лампу.» (667 мс), small — прежнюю ошибку (1664 мс). Padding не добавлен.

Эти одиночные времена включают загрузку модели и зависят от кеша ОС. Они не
являются benchmark и не дают оценки точности живой речи. Результат показывает,
почему editable STT review остаётся необходимым, а заявленная высокая точность
русской речи требует дальнейшего эксперимента на человеческих записях.

**Нормальный HTTP/CLI путь voice в этой sandbox-среде не подтверждён.**
Python 3.14 TemporaryDirectory создаёт user-only ACL, исключающий sandbox SID.
Production ACL не ослаблялась; direct worker использовал проектный scratch с
синтетическим аудио. Обычный `eval_stt.py` на одной synthetic записи корректно
вернул 503 «Временное хранилище … недоступно», successful=0, failed=1,
WER/CER=null и код выхода 1. Это ограничение среды, а не успешная end-to-end
приёмка STT/TTS API. На обычной Windows-сессии нужно повторить весь путь.

Реальные маршруты FastAPI дополнительно вызваны TestClient с loopback peer,
реальными загруженными моделями и `.voice-deps`, без mock voice. И
`POST /api/transcribe` на synthetic WAV, и `POST /api/tts` вернули **503** с
`detail`: «Временное хранилище голосового модуля недоступно. Проверьте права ОС
и свободное место.». Это подтверждает корректный отказ API в данной среде,
а не успешное распознавание/синтез через production tempfile.

## Воспроизводимый прогон

```powershell
.\.venv\Scripts\python.exe -m pytest --collect-only -q
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe start.py
```

Если окружение ещё не создано, сначала используйте setup из README. Установка
зависимостей и моделей — отдельный сетевой этап, не часть нормального запуска.
Проверка voice статуса: `python -m localmind.voice status`.

## Согласованные записи и точность

Фразы перечислены в `docs/STT_TEST_SET.csv`, но аудиофайлов там нет. Запишите
не менее 30 фраз каждого согласившегося участника; отдельно тихое помещение,
обычный фон и разные расстояния до микрофона. Сохраните эталон до запуска STT,
чтобы не переписывать правильный ответ под результат модели. Не называйте
множество фраз случайной выборкой, если оно подбиралось вручную.

CSV содержит `id,path,reference`, пути относительно CSV:

```powershell
.\.venv\Scripts\python.exe scripts/eval_stt.py recordings.csv --consent --profile cpu-fast
.\.venv\Scripts\python.exe scripts/eval_stt.py recordings.csv --consent --profile balanced
.\.venv\Scripts\python.exe scripts/eval_stt.py recordings.csv --consent --profile gpu-quality
```

Используйте одни и те же записи для сравнения профилей. Скрипт выводит число
ошибок и длины эталонов, WER/CER, latency каждой записи, среднее, максимум,
p50 и p95 методом ближайшего ранга;
ошибки обработки учитываются отдельно. Тексты не выводятся. Нормализация:
нижний регистр, ё→е, удаление пунктуации, CER без пробелов. WER иногда больше
100% при множестве лишних слов; это не ошибка формулы. Информация о нормализации
обязательна при сравнении с чужим исследованием.

## Задержка и память

Для каждого профиля сделайте минимум 30 повторов после отдельного первого
прогона. Храните первый прогон отдельно и укажите число успешных/неуспешных.
Процесс голосовой операции загружает модель заново: даже повторный запрос
включает model load. Файловый кеш ОС может ускорять повтор; это нужно описать.

Отсортируйте успешные времена: p50 и p95 — значения рангов `ceil(0.50*N)` и
`ceil(0.95*N)` (с нумерацией от 1). Не скрывайте неуспешные запросы за хорошими
перцентилями; рядом показывайте их долю. Для STT отдельно вычислите real-time
factor: время обработки / длительность записи.

Измеряйте `action_ms`, `llm_ms`, суммарное время и момент появления status в
браузере. Для GPU запишите модель карты, драйвер, CUDA/CTranslate2, VRAM до/во
время опыта, модель Ollama и выполнялась ли она одновременно. Для CPU укажите
модель процессора, потоки, RAM, Python и версии зависимостей. Память worker и
основного сервера измеряйте отдельно; инструмент замера сам влияет на результат.
Никаких чисел пиковой RAM/VRAM в этом прогоне не получено.

## Проверки отказов и offline

После загрузки активов отключите внешнюю сеть и перезапустите LocalMind.
Проверьте лампу DEMO, образовательный ответ, распознавание с редактированием,
Piper start/stop/mute, локальную математику и Markdown. Отдельно остановите
Ollama после факта действия: статус должен остаться, действие не повторяться.
Одинаковый request_id отправьте одновременно дважды с тестовым адаптером и
сравните число его вызовов; другой текст с этим ID должен дать 409.

Ручная проверка Windows: обнаруженные программы, повторное разрешение после
обновления, неизвестное/неоднозначное имя, безопасный отказ закрыть несохранённый
Блокнот. Home Assistant проверяется только на реальном настроенном устройстве
с разрешением владельца. Сохраните точные команды и наблюдения, не токены и аудио.
