# Единое хранилище и память моделей — проверка кандидата

Дата: 03.11.2026. Это реализация для проверки, а не завершённая Windows-приёмка.

После установки зависимостей одна команда запуска: `python start.py`
(либо существующий `.\start_windows.ps1`). Офлайн-демо после загрузки ресурсов:
запустить Ollama, выбрать уже установленную Gemma, спросить «Что такое RSA-шифрование?»,
включить xenia, затем DEMO: «Включи настольную лампу» и «Не включай настольную лампу».
Загрузка ресурсов требует сети, inference остаётся локальным.

## Поведение

Приоритет: явный `LOCALMIND_DATA_DIR` → сохранённый выбор
`%LOCALAPPDATA%\LocalMind\config\storage-location.json` → `%LOCALAPPDATA%\LocalMind`.
Root разрешается до settings/worker imports, передаётся дочерним процессам через окружение.
Переменная из внешнего окружения имеет приоритет также после перезапуска;
UI явно сообщает об этом. В `.env` root не задаётся: он нужен раньше dotenv.

Настройки → Дополнительно → Хранилище данных: новый абсолютный каталог,
проверка плана с источником/назначением/объёмом/местом, отдельное согласие,
копирование с SHA-256, затем перезапуск. Источник никогда не удаляется;
существующий отличающийся файл вызывает конфликт. При сбое повторить план:
проверенные одинаковые файлы используются повторно. До перезапуска после смены
root изменяющие HTTP-запросы блокируются, чтобы не терять новые изменения.
Незавершённые чат-запросы (включая finish_turn), benchmark и загрузки блокируют перенос.
Не переносится webcache и незавершённые .partial/.tmp/.lock. Иные неизвестные файлы
в выбранном текущем root считаются его данными и включаются в согласованный объём.

Группы: `models/llm`, `models/whisper`, основной TTS `models/silero`, дополнительные
`models/piper`/`models/chatterbox-v3`, `config`, `history`, `logs`, `downloads`.
Старые имена `private/active-model.json`, разрешений, HA-конфигурации и журнала
поддержаны ради совместимости. Новые загрузки используют `downloads/jobs.json`;
при существующем `private/downloads.json` он используется без потери задач.
История чата по-прежнему opt-in в browser storage, а не автоматически записывается
в каталог history. EXE webprofile входит в root; профиль обычного браузера принадлежит
браузеру. Не обещается перенос его истории в EXE. Поля генерации сохраняются сервером
по моделям после изменения пользователем и одинаково восстанавливаются в обоих UI.

Ollama: показывается каталог из окружения процесса, реально слушающего настроенный
loopback endpoint. На Windows default вычисляется из USERPROFILE этого процесса.
Без доступа к процессу каталог остаётся неизвестным; клиентский `OLLAMA_MODELS`
не считается доказательством. Gemma и её внешнее хранилище используются на месте.
Для нового каталога Ollama есть отдельный план копирования существующего подтверждённого
store; он не переключает сервер. Для общего сервера UI выдаёт точные шаги задания
пользовательского `OLLAMA_MODELS` и ручного Quit/restart. LocalMind не меняет системную
конфигурацию и не останавливает общий сервер. Если endpoint свободен, по отдельному
согласию можно запустить `ollama serve` с выбранным OLLAMA_MODELS; путь подтверждается
по PID/времени старта и слушателю, а не факту запуска процесса.

Память: `/api/ps` показывает loaded; выбор LocalMind — active/inactive;
счётчик lease — being-used. Inactive не означает простой других клиентов.
Cleanup выполняется в finally после benchmark/проверки переключения, включая ошибки
и отмену. При общем или потенциально общем сервере автоматическая выгрузка пропускается
с объяснением. Даже запущенный LocalMind loopback daemon потенциально доступен другим
приложениям: владение PID не равно эксклюзивности. Расширенная политика сохраняет
keep_alive (0–900 секунд), cleanup временных моделей и предпочтение выгрузки предыдущей.
Ручная выгрузка требует явного подтверждения отсутствия внешних запросов;
активная/используемая LocalMind модель сохраняется. Используется поддерживаемый
`POST /api/generate` с `keep_alive:0`, затем проверяются отсутствие в `/api/ps`
и сохранение в `/api/tags`; сбой проверки не выдаётся за успех. DELETE не используется.

Источники интерфейсов проверены при разработке:
[Ollama running models](https://docs.ollama.com/api/ps),
[keep_alive](https://docs.ollama.com/api/generate),
[Windows environment и model storage](https://docs.ollama.com/faq).

## Восстановление

- Ошибка ссылки/reparse point: выберите обычный локальный каталог. Ссылки не обходятся.
- Конфликт: выберите пустой каталог либо отдельно разберите конфликт; LocalMind не удаляет файлы.
- FAT/exFAT или запрет hard links: копирование безопасно завершится ошибкой; используйте
  NTFS с поддержкой hard links. Источник и прежний root сохраняются.
- Ошибка прав bootstrap: выбор не сохранён; исходники остаются. Не требуются ACL-обходы.
- Неизвестный Ollama store: запустите обычный локальный Ollama и проверьте пути ещё раз;
  переменная клиента не исправляет окружение уже запущенного сервера.
- Модель остаётся loaded после выгрузки: UI сообщает unverified; не удаляйте её файлы.
- Источник изменился: дождитесь операций и сформируйте новый план.

Реальная read-only проверка этого ПК подтвердила Ollama 0.40.13, внешний store
`C:\Users\ExampleUser\.ollama\models`, installed `gemma4:12b`, RTX 4070 и около 32 GB RAM.
Это обнаружение, не тест генерации Gemma, GPU STT, совместной нагрузки или чистой установки.
Ни один реальный пользовательский store не переносился; общий Ollama не выгружался.
