# Download Manager — проверка этапа 3

Дата: 03.11.2026. Это рабочий протокол проверки, а не подтверждение готовности Windows-релиза.

## Что изменено

Каталог и окно «Загрузки» используют один renderer и один durable `JobStore`.
Новые журналы находятся в `downloads/jobs.json` выбранного data root. Старый
`private/downloads.json` читается при отсутствии нового; исходный файл сохраняется.
После перезапуска активная задача становится прерванной, байты и назначение остаются;
автоматического повторного pull нет. Журнал ограничен 32 последними задачами.

Байты Ollama агрегируются по digest слоёв заменой значений, а не суммированием событий.
Начальный cached progress не считается скоростью сети. Скорость появляется после
измеренного положительного прироста за минимум секунду; новый слой, изменение total,
сброс счётчика и перезапуск сбрасывают измерение. В UI устаревшая скорость скрывается.
ETA относится только к уже известным слоям: Ollama может объявить следующие позже.
Индикатор без известного total остаётся неопределённым. «Установлена» требует конца
NDJSON и проверки `tags/show`; SHA-256 HF и offline GGUF сверяется с подтверждённым
артефактом. Отсутствующий или несовпавший SHA-256 daemon не даёт состояния «Установлена».

Отмена сначала показывает «Отмена запрошена». Закрытие pull stream завершается
`cancelled_unverified`, поскольку это не доказательство остановки общей загрузки
в daemon. «Скрыть запись» сохраняет dismiss в журнале и не удаляет модель. Повтор
доступен только для неудачной/прерванной/отменённой задачи. HF metadata, лицензия,
fingerprint и диск проверяются снова; offline retry также связан с прежними
SHA-256/размером/лицензией. Успешная установка не переключает активную LLM.

Лицензия изначально не принята. Проверяется диск фактического Ollama server process,
а не окружение Python-клиента. При неизвестном месте ручное разрешение доступно
только в экспертном UI; известную нехватку места обойти нельзя. При неизвестном размере
артефакта нужно обновить карточку или выбрать другой вариант. Offline Qwen обозначен
как лёгкая резервная/тестовая модель. Для другого GGUF сборщик должен явно указать
`--offline-model-name`; название в manifest является сведением сборщика, не результатом
автоматического определения архитектуры.

## Ручная QA на Windows — выполнить отдельно в EXE и Python

Запуск подготовленной Python-среды одной командой: `python start.py`.
Для EXE используйте установленный LocalMind. Перед тестом запишите активную Gemma,
контекст, reasoning, response budget и retention; после каждого шага сравнивайте их.
Все строки ниже пока требуют реального прогона; авто-тесты их не заменяют.

| Действие / точный ввод | Ожидаемый результат |
|---|---|
| Модели → HF: `Qwen2.5-0.5B-Instruct-GGUF`; выбрать `Qwen/Qwen2.5-0.5B-Instruct-GGUF`, Q4_K_M | Показаны издатель, лицензия, размер; лицензия не отмечена; загрузка сама не стартует |
| Нажать «Установить» без принятия лицензии | Понятное требование согласия; новый pull не создан |
| Принять лицензию и начать при подтверждённом диске | Открывается менеджер: имя, фактическое назначение, реальные байты и progress bar; Gemma активна |
| Во время pull перейти в чат, снова открыть «Модели» и «Загрузки» | Одна задача с тем же id и байтами; оба представления используют одни состояния |
| Нажать «Отменить» | Сначала запрос отмены; затем закрытый поток с явной неподтверждённой остановкой Ollama. Нет ложного «отменено» для daemon |
| Закрыть приложение во время pull, открыть снова | Задача прервана, байты/назначение сохранены. Ни автоматического retry, ни обещания остановки daemon |
| Нажать «Повторить» после interrupted | Проверка актуальных metadata/диска; новая явная задача. При изменённой лицензии/артефакте нужно открыть карточку и подтвердить её заново |
| Дождаться конца загрузки | Сначала проверка, затем «Установлена» после tags/show/SHA. Активная Gemma и её настройки сохранены |
| Нажать «Скрыть запись», перезапустить | Запись скрыта; модель остаётся в установленных. Установить модель не означает активировать её |
| Проверить недоступный диск Ollama | В обычном UI нет checkbox обхода. Экспертный override возможен только при неизвестной доступности |
| На отдельном тестовом диске оставить места меньше требуемого | Отказ до pull даже при явном override; никакой обход известной нехватки |
| Offline-комплект: импорт без лицензии, затем с лицензией | Сначала отказ; затем проверенный импорт. Qwen подписан «лёгкая резервная/тестовая модель», Gemma не меняется |
| Gemma: `Что такое RSA-шифрование?` | Связный ответ текущей основной модели; установка/отмена не переключает её |
| Silero xenia: озвучить этот ответ | Слышна xenia; выбранный голос сохранён |
| Windows: `Открой ноутпад` | Запуск только подтверждённого локального приложения по существующей политике |
| Windows: `Не запускай калькулятор` | Калькулятор не запускается |
| Home Assistant DEMO: `Включи настольную лампу`, затем `Не включай настольную лампу` | Первый ввод меняет DEMO-состояние по существующей авторизации; второй не выполняет действие |
| После подготовки моделей отключить интернет, перезапустить, задать RSA и озвучить | Gemma и xenia работают локально; журнал доступен. HF поиск сообщает о сети, а не имитирует успешную загрузку |

Не проверены настоящим прогоном этого этапа: полный HF pull/cancel/retry на daemon,
Windows microphone, прослушивание xenia, RTX 4070 под совместной нагрузкой,
EXE/installer и offline demo. Приёмка релиза остаётся открытой до этих проверок.

## Troubleshooting

- Неизвестен диск: «Настройки → Дополнительно → Хранилище данных», проверить путь и
  источник подтверждения Ollama. Изменение переменной клиента не меняет уже запущенный
  сервер. Для общего сервера используйте явные инструкции настройки и перезапуска.
- Retry просит карточку: metadata/лицензия/артефакт изменились либо старый журнал
  не содержит прежнего подтверждения. Откройте актуальную карточку и подтвердите её.
- «Поток закрыт»: проверьте установленные модели; общий Ollama может продолжать pull
  другого клиента. Не удаляйте модели ради «освобождения VRAM».
- Повреждён журнал: сохраните его копию для диагностики и восстановите хранилище;
  программа не затирает повреждённый файл и не запускает потерянные задачи сама.
- Неизвестна скорость: ещё нет достаточного прироста байтов, слой закеширован,
  изменился total либо события устарели. Это не ошибка и не основание рисовать ETA.
