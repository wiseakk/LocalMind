# Model Manager: запуск, демонстрация и ручная проверка

Запуск после установки зависимостей: `python start.py` (в активированном venv).
Из корня Windows checkout без активации: `.\.venv\Scripts\python.exe start.py`.
Дополнительная телеметрия: `python -m pip install -r requirements-monitoring.txt`.
Настройки → Модели ИИ. Обновление показателей не запускает inference или загрузку.
После предварительной установки Ollama, LLM, ASR и xenia обычный чат и голос
работают локально. Каталог HF требует интернет только при явном поиске/просмотре,
а скачивание — отдельного нажатия. Проверку с отключённой сетью проводить после
загрузки всех ресурсов. Сам факт успешного локального HTTP не доказывает офлайн.

Сырые metadata результатов в .test-artifacts/models/phase2-real.json.
Числа likes/downloads не используются. Benchmark для конкретного варианта
не подтверждён; вместо него выводится явное отсутствие данных. Curated
Ollama варианты имеют source URL и дату; KV формула: 2 × layers × kv_heads ×
head_dim × 2 bytes × context + веса + 1 GiB runtime. Рекомендация добавляет
20% и 2 GiB на конкуренцию ASR. Если размеры KV отсутствуют в metadata,
RAM/VRAM estimate неизвестна. Источники KV: опубликованные config.json
Qwen/Qwen3-4B и Qwen/Qwen3-8B на HF. Контекст 4096 остаётся рекомендацией.

Свободное место по умолчанию неизвестно: backend не знает хранилище отдельного
daemon. Оператор может задать `OLLAMA_MODELS` и
`LOCALMIND_OLLAMA_STORAGE_VERIFIED=true` только после проверки, что daemon
использует этот путь. Путь в браузер не передаётся. При неизвестном диске/размере
требуется отдельное подтверждение ручной проверки. Ошибка диска во время pull
переводит задачу в failed; ошибки не раскрывают сырые исключения/токены/пути.
После рестарта фоновые задачи не возобновляются. Явный повтор использует
поддерживаемый Ollama pull, который может переиспользовать сохранённые слои.
Отмена закрывает HTTP поток; общий pull другого клиента daemon может продолжать.

## Этап 3: тест модели и сравнение

Набор `config/model_benchmark.json`, версия `localmind-ru-screening-v2`:
12 фиксированных вопросов и опубликованные expected/check. Факты, инструкции,
рассуждения, код, неопределённость, structured и native tools показываются
раздельно. Не-tool ответы ограничены JSON schema с полем answer; structured
задание имеет свою schema. Это помощь формату, поэтому метод явно указан.
История состоит из одинаковых system/user и закрывающего think assistant-prefill
для всех моделей. Контекст 4096, seed 42, temperature 0, budget 256, think false,
num_gpu -1. Даже такой запрос не доказывает фактическую GPU загрузку: placement
записывается после прогона через `/api/ps` и показывается в результатах.

Реальное сравнение qwen3:4b и qwen3.5:9b завершило 24/24 задания. У каждой:
factual 3/3, instruction 2/2, reasoning 2/2, coding AST 1/1, uncertainty 1/1,
structured 1/1, native tools 0/2. Это строгий screening малой выборки,
не семантическая точность или общий quality score. qwen3:4b оставалась на CPU
после CPU fallback; qwen3.5:9b — на GPU. Прямой вывод о скорости запрещён.
Измеренные средние 2450.286 / 591.263 ms и 23.759 / 46.012 tokens/s относятся
именно к этим разным placements. Обе quant Q4_K_M; полный digest, hash набора,
ответы, проверки и метрики — в [реальном отчёте](evidence/model-manager-20261101.json).

На последнем коде также проверен реальный HTTP-сценарий на отдельном
`python start.py` / порту 8879: запуск теста qwen3.5:9b 200, чат во время теста
429, повтор с тем же request_id после освобождения 200, настоящий JSON и NDJSON
с actual_model qwen3:4b и метриками. Активная модель до/после совпадает.
Предварительная версия v1 выявила неподходящий свободный формат ответов и
исчерпание output budget; она не используется как подтверждение качества v2.

| Точный сценарий | Ожидается; признак ошибки | Фактически |
|---|---|---|
| Выбрать qwen3:4b и qwen3.5:9b → «Тестировать / сравнить» | 24 одинаковых задания/settings, отдельные scores, digest/hash, активный выбор прежний | Реальный модуль; HTTP одной модели; UI только DOM |
| Во время теста отправить «Привет» | Busy без резервирования request ID; повтор после окончания работает | Реальный HTTP 429 → 200, плюс тест replay уже принятого запроса |
| «Прервать после текущего задания» | Следующее задание не начинается, incomplete; ошибка: completed при неполном наборе | Автотесты, реальное прерывание не проверено |
| Модель без tools | Native tools N/A, structured отдельно; ошибка: выдуманный 100% tool score | Автотесты |
| Изменить digest модели во время теста | incomplete; ошибка: выдать воспроизводимое полное сравнение | Автотесты; реальные теги не менялись |
| Поставить ручной рейтинг 4 | Отдельное поле, автоматические checks не меняются; ошибка: смешать рейтинг с factual | Mock/persistence/DOM; человеческий рейтинг не выставлялся |
| Модель возвращает код или tool call demo_action | Только проверка данных, ни одного OS-вызова | Автотесты; реальные tool tests не запускали приложение |
| Повторить голос, историю, вложения, stop/mute, масштабы из этапа 1 | Регрессий нет; ошибка: потеря прежних функций | Полные Python/DOM тесты; микрофон/звук/визуальная проверка не подтверждены |

Результаты синтетических тестов сохраняются в управляемом `results/private`,
включая текущий checkpoint; при рестарте незавершённый тест становится incomplete,
без автопродолжения. Если запись не удалась, UI сообщает о неполных/несохранённых
результатах. Ошибки/неизвестные метрики не превращаются в quality scores.
Бенчмарк занимает общий inference lock; инструменты только объявлены. Код
сравнивается через AST, не запускается. Tests не используют subprocess evaluator.

Полная приёмка остаётся открытой: реальные download/cancel/retry, одновременный
GPU ASR, Windows microphone и слышимость xenia, отключённая сеть и визуальные

проверка разрешений отклонила чтение Zen: Computer Use не одобрен для браузера.
Обойти эти ограничения не пытались. Git add/commit также запрещён внешним index
вне writable workspace; три запрошенных focused commits создать не удалось.

Итог автоматических проверок этого checkout: 68 focused passed; полный pytest
780 passed, 4 skipped (один warning о deprecated httpx TestClient adapter).
JS syntax, 39 основных DOM checks и отдельные attachment/history/model checks,
77 local assets, compileall и git diff --check прошли. Playwright: 36 обнаруженных
тестов, worker не запущен; это не 36 пройденных браузерных тестов.
На последнем коде повторены реальный inventory (3 модели), health qwen3.5:9b и
HF variants (5 вариантов, fingerprints). Переход к pull повторно сверяет

нового согласия, без загрузки. Тесты покрывают explicit retry и ошибки запуска
фонового worker. Старт/остановка собственного сервера 8879 не меняли чужие процессы.
