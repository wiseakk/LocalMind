# Linux rc3-4 — повторный запуск Desktop

## Воспроизведение

Проверка установленного rc3-3 на CachyOS/Hyprland использовала временный
XDG-профиль и порт 58603. В каждом цикле WebEngine загружал интерфейс, отдельный
локальный клиент запрашивал `GET /api/info`, после чего окно штатно закрывалось.

На втором закрытии `ss -Htan sport = :58603` показал `TIME-WAIT` и ни одного
`LISTEN`. Третий процесс получил `OSError`, errno **98 / EADDRINUSE**, до
появления HTTP-сервера. Старый диалог ошибочно предлагал закрыть другую копию.
`start.py` использует управление listener самим Uvicorn, а Qt Desktop
передавал Uvicorn уже привязанный Python-сокет.

## Изменение и диагностика

Перед bind на POSIX задаётся `SO_REUSEADDR`. Windows продолжает пользоваться
`SO_EXCLUSIVEADDRUSE`. При конфликте Desktop коротко проверяет, принимает ли
loopback-порт соединения. Если слушатель не обнаружен, диалог объясняет
временную TCP-блокировку как возможную причину. Ошибки настроек, таймаут
backend, ошибки backend и Qt получают отдельные сообщения.

При завершении Desktop отправляет Uvicorn сигнал `should_exit`, ждёт thread
и закрывает listener в `finally`. Сетевой listener освобождается также при
ошибке Qt и нештатном старте backend. При истечении предельного ожидания
появляется отдельная запись в журнале.

Последняя причина хранится в `logs/desktop-error.json` текущего профиля,
обычно в `~/.local/share/LocalMind/logs/desktop-error.json`. Запись содержит
этап, тип исключения, errno и имена файлов с номерами строк. Текст исключения,
абсолютные пути и содержимое ASGI traceback в запись не попадают. Первичная
ошибка startup имеет приоритет перед последующим завершением Uvicorn.

## Установка и проверка

Финальный архив проверен после извлечения на системном Python под Wayland.
**20 из 20** последовательных процессов открыли WebEngine, ответили HTTP 200
и штатно завершились. После каждого не было LISTEN. К концу серии осталось
12 TCP-записей TIME-WAIT. При настоящем занятом порте чужой сокет сохранился.
При инъекции отказа запуска ASGI (`PermissionError`, errno 13) и исключения Qt
(`RuntimeError`) диагностический этап различался, listener освобождался,
контрольная секретная строка отсутствовала в журнале и выводе процесса.

Pytest: **1745 passed, 31 skipped, 35 subtests passed**. В том числе проверены
живой TCP TIME-WAIT, эксклюзивность bind, очистка даже при таймауте и удаление
сырого traceback из уведомления ASGI. Логи прогонов: `.test-artifacts/rc3-3-relaunch.log`,
`.test-artifacts/rc3-4-relaunch-final.log`, `.test-artifacts/rc3-4-faults-final.log`.

SHA-256 `8701129128279e5b3618df8b4d7fb0d97ea5b632abe27b25e78ad0e7ed79d519`.

Из корня checkout:

```sh
sudo pacman -U .test-artifacts/rc3-4-final-release/localmind-1.0.0rc3-4-x86_64.pkg.tar.zst
gtk-launch localmind
```

Закройте окно после появления интерфейса и сразу снова откройте LocalMind
из меню. Повторите несколько раз. Для проверки HTTP во время работы используйте
`curl --noproxy '*' http://127.0.0.1:8765/api/info`. После закрытия проверьте
`ss -tan 'sport = :8765'`. Записи `TIME-WAIT` допустимы. Если появится диалог
сбоя, сохраните `desktop-error.json` и состояние сокетов.

Системная установка новой версии оставлена для ручной приёмки. Тесты
использовали временные профили и loopback-порты. Ollama и голосовой контур
в рамках этого исправления не проверялись.
