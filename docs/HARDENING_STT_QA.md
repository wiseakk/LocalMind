## Установленные факты

Сравнение `git diff 3e0a228 66f6c10 -- localmind/voice.py localmind/asr_worker.py localmind/stt_worker.py` показывает:
публичные профили и декодирование не изменились. Изменились каталог ресурсов, выбор Python runtime
и проверка целостности small. Прежний коммит не является подтверждённой рабочей сборкой пользователя.
Причина «Пак варить пельмени» пока **не установлена**. В этой правке модель и параметры распознавания
сохранены; замена слов после ASR не добавлена.

Профили: `cpu-fast = base / CPU / int8`, `balanced = small / CPU / int8`,
`gpu-quality = medium / CUDA / float16` с fallback на CPU int8. Каждый профиль теперь отдельно
подготавливается через «Подготовить голос / восстановить». Base и medium закреплены на ревизиях
`ebe41f70d5b6dfa9166e2c581c45c9c0cfc57b66` и `08e178d48790749d25932bbc082711ddcfdfbc4f`.
Контрольные суммы получены из официальных HF metadata LFS и хешированием небольших файлов;
веса при разработке не скачивались. Small и xenia сохранены.

Источники: [faster-whisper](https://github.com/SYSTRAN/faster-whisper),
[base metadata](https://huggingface.co/api/models/Systran/faster-whisper-base?blobs=true),
[medium metadata](https://huggingface.co/api/models/Systran/faster-whisper-medium?blobs=true).
Проект декодирует запись через PyAV в 16 kHz mono, не обрезая начало до VAD.
`getUserMedia({audio:true})` сохранён: настройки обработки микрофона не менялись без записей для сравнения.

Экспертная «Проверить инфраструктуру» показывает сведения последнего реально загрузившего ASR worker:
абсолютный путь, SHA-256 четырёх файлов, подтверждённое/неизвестное происхождение, Python executable,
версии библиотек, requested/actual device и compute type, fallback, VAD, beam, время загрузки и inference.
До запроса показывается `not_loaded`. При выгрузке worker загруженная идентичность сбрасывается.
Технический журнал после микрофона содержит разрешённые поля `getSettings()` (sampleRate, channelCount,
echoCancellation, noiseSuppression, autoGainControl, latency), MIME контейнера/кодека. Device ID не сохраняется.
Если браузер поле не возвращает, оно остаётся неизвестным. Записи и transcript в кэше диагностик не хранятся.

RAM — RSS всего worker после запроса, VRAM — память процесса по NVML при доступности драйвера.
Это не пик и не память только весов; при WDDM измерение VRAM может быть неизвестно.
Замеры профиля показывают CPU/GPU и actual device. До первого запроса числа не подставляются.

Совместимость `WHISPER_MODEL`: допустимые base/small/medium задают только профиль по умолчанию.
Явно выбранный профиль HTTP/CLI или сохранённый выбор браузера приоритетнее. Другие значения,
пути и URL не выбирают модель; используется balanced. Без переменной default — balanced.
CLI для экспериментальных моделей сохранён отдельно и не запускается автоматически.

## Сравнение одинакового корпуса

Manifest CSV: `id,path,reference,condition`; пути относительно manifest. Для каждой сборки сохранить
JSONL вывод отдельно (согласованные аудиозаписи не добавлять в Git). Одна команда запуска приложения:
`python start.py`. После подготовки ресурсов распознавание и озвучка работают локально без загрузок.

```powershell
python scripts/eval_stt.py recordings.csv --profile balanced --consent --hardware-note "Windows, микрофон, CPU/GPU, условия"
python scripts/eval_stt.py recordings.csv --profile cpu-fast --consent
python scripts/eval_stt.py recordings.csv --profile gpu-quality --consent
```

Для EXE использовать его приватный runtime и явно выбрать **код той же сборки**:

```powershell
& 'C:\LocalMind\runtime\core\python.exe' scripts/eval_stt.py recordings.csv --app-root 'C:\LocalMind' --profile balanced --consent
```

Идентичность ресурсов и runtime в JSONL должна совпадать с диагностикой EXE. Для прежней сборки без новой
диагностики сначала установить фактическое расположение и настройки — старый Git commit этого не доказывает.
`--include-transcripts` явно включает приватные исходные тексты. По умолчанию они не печатаются.
`--matrix` включает большие экспериментальные модели; не устанавливает их и не нужен для трёх публичных профилей.
Сравнить WER/CER, technical_name_accuracy, negation_retention, negated_phrase_exact_accuracy и latency
на одинаковых SHA-256 аудиозаписей. Не принимать baseline с изменившимися байтами.

## Troubleshooting и ограничения проверки

При отсутствии модели подготовить именно выбранный профиль. При несовместимых DLL восстановить runtime;
GPU не означает автоматически установленные CUDA/cuDNN. При тихом/клиппированном входе посмотреть levels
и capture settings, затем повторить запись. Не заменять ошибочную фразу словарём «правильных» ответов.
При отличиях EXE/Python сравнить runtime executable, версии PyAV/faster-whisper/CTranslate2, SHA-256 и root.

Автотесты проверяют в том числе реальные декодирование 48 kHz stereo → 16 kHz mono и транспорт worker
на тишине; эти сигналы не являются проверкой точности речи. Реальные Windows-микрофон, качество фразы,
подтверждённый пользовательский baseline, RTX 4070, installer и слышимая xenia здесь не проверены.
Существующий `docs/DEFENSE_QA.md` сохраняет объяснения для защиты; эта правка их не заменяет.
