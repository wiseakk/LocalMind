# Как устроен LocalMind 1.0

LocalMind — однопользовательское приложение на компьютере Windows. Браузер
показывает диалог и записывает звук по кнопке. Python-сервер проверяет запросы,
Ollama формирует текст, faster-whisper распознаёт речь, Piper синтезирует русский
голос. Голосовые модели и LLM загружаются отдельно до работы без интернета.

## Путь одного запроса

1. Пользователь печатает текст либо записывает фразу. STT возвращает черновик;
   исправление и явная отправка обязательны для голосовой команды.
2. `server.py` проверяет loopback-клиента, Host, Origin, необязательный ключ,
   размер запроса и структуру JSON. Заголовкам reverse proxy не доверяют.
3. `requests.py` связывает `request_id` с отпечатком всего запроса. Совпадающий
   повтор получает тот же результат; другое содержимое с тем же ID получает 409.
4. `agent.prepare_reply` определяет допустимое намерение по проверяемым правилам.
   Отрицания, цитаты, несколько целей и смешанные команды не исполняются.
   `actions_authorized=false` возвращает предварительный просмотр.
5. Для точного разрешённого действия адаптер выполняется один раз и возвращает
   `ActionResult`. В нём отдельно записаны принятие операции, наблюдаемое
   состояние, ошибка, длительность и режим DEMO/REAL.
6. `/api/chat/stream` сначала отправляет строку NDJSON с `type: status`.
   Браузер уже показывает правдивый статус. Затем `complete_reply` вызывает
   отдельный Ollama composer без инструментов и отправляет `type: final`.
   `/api/chat` использует тот же обработчик, но ждёт окончательный JSON.
7. Composer получает JSON фактов и недоверенный пользовательский текст. Его JSON
   должен точно повторить success, execution_status и observed_state. Проверки
   отбрасывают ряд противоречий и подозрительное содержимое; ошибка генерации
   сохраняет исходный статус. Полного доказательства истинности свободного
   текста эти проверки не дают — статус действия всегда показан отдельно.
8. Rich-renderer обрабатывает Markdown через локальные marked и DOMPurify, затем
   KaTeX. При недоступных библиотеках остаётся обычный текст. TTS получает текст
   через отдельный endpoint; команды из речи синтезатора не исполняются.

Важное различие: `process_created` подтверждает создание процесса, а не появление
окна. `request_accepted` подтверждает приём команды Home Assistant, а не горящую
лампу. Только DEMO-адаптер наблюдает собственное состояние симуляции напрямую.

## Разделение ответственности

| Модуль | Что студент должен уметь объяснить |
|---|---|
| `server.py` | Граница HTTP, схемы входа, защита loopback, endpoints |
| `agent.py` | Отличие информационного вопроса от разрешённой команды |
| `results.py` | Зачем отдельно хранить успех, исполнение и наблюдение |
| `requests.py` | Блокировка гонки дублей; почему повтор генерации не повторяет действие |
| `devices.py` | Разница DEMO и Home Assistant; запрет неизвестных устройств |
| `apps.py` | Источники каталога, проверка PE, отпечатки и разрешения |
| `voice.py` | Профили, VAD, CPU fallback, границы ресурсов и дочерний процесс |
| `static/assets/app.js` | Черновик речи, последовательные статусы, состояние интерфейса |
| `localmind-rich.js` | Санитизация, локальные зависимости, Markdown и LaTeX |
| `scripts/eval_stt.py` | Расстояние редактирования, WER/CER и измеренная задержка |

## Каталог приложений

Windows Known Folders задают Start Menu/Desktop, App Paths — дополнительный
источник регистраций. Ярлык читается через COM без запуска и без Resolve.
Метаданные считаются недоверенными. Разрешены только поддержанные GUI `.exe`
с локальным абсолютным путём, валидным PE-заголовком и без аргументов. Скрипты,
оболочки, URL, установщики и неизвестные executable имена отклоняются.

ID связан с источником записи; разрешение — с SHA-256 отпечатком источника,
пути и содержимого executable. При запуске источник и файл проверяются повторно,
а Windows handle препятствует записи/удалению образа во время создания процесса.
После обновления приложения разрешение требуется выдать заново. Разрешения
сессионные. Калькулятор и Блокнот дополнительно поддержаны через системный путь.
Наличие имени в словаре псевдонимов не означает наличие установленного приложения.

Это защита от использования метаданных как команды, а не антивирусная проверка
программы. Пользователь должен доверять программе, которой выдаёт разрешение.
Автозакрытие окон запрещено: приложение не может гарантировать сохранность
несохранённого текста и принадлежность окна своему процессу.

## Что именно локально

Интерфейс, Markdown, шрифты, STT, TTS и LLM inference могут работать без интернета
после отдельной установки ресурсов. Home Assistant — дополнительная локальная
сеть только по конфигурации владельца; по умолчанию включён DEMO. Облачного
fallback для голоса нет. История хранится в памяти вкладки; временное аудио
удаляется. LAN-доступ к самому LocalMind и постоянное прослушивание не реализованы.

## Авторство и защита проекта

Код создавался с помощью AI-агентов. Это нужно прямо назвать на защите. Нельзя
заявлять, что ученик самостоятельно написал или измерил то, чего не делал.
Проверяемый личный вклад: постановка требований, выбор безопасной архитектуры,
объяснение маршрутизатора, разработка/проверка набора фраз, проведение собственных
экспериментов и воспроизводимая демонстрация исправлений.

Перед выступлением каждый автор должен пройти один запрос по коду, объяснить
одну отрицательную проверку, изменить маленькое правило и показать тест. Если
авторов двое, можно согласовать разделение: первый — API/авторизация/действия,
второй — голос/UI/эксперименты. Это предложение ролей, а не факт выполненной работы.
Фактический вклад и выполненные измерения вписываются авторами после проверки.
