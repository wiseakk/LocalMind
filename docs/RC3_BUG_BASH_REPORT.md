# LocalMind RC3. Аудит перед выпуском

**Вердикт: RELEASE BLOCKED.** Отдельная чистая Windows 10/11 отсутствует.
Полный сценарий установки, разговор через физический микрофон и проверка
GPU/CPU в голосовом контуре остаются воротами выпуска. Проверки Windows
выполнялись с отдельными профилями на компьютере, где Ollama и модели уже есть.

Ветка `qa/rc3-full-bug-bash` начата от `84cbb86bc9f2020c7690f7b4b6ff1e2eb5d15d8a`,
потомка `a28e6c3`. База включает перечисление папок и рабочие зеркала Whisper.
Патч и отчёт находятся в коммите `fix(rc3): harden routing and desktop flows after bug bash`.

## Карта возможностей

`file_access.py`, `personal_permissions.py`, `window_tools.py`, `home_routes.py`,

В исходном браузерном прогоне выявлены также проблемы стенда. В `ui.spec.mjs`
ответ `/api/setup` не содержал завершённое onboarding-состояние, поэтому
проверки рабочего чата и клавиатуры перекрывались мастером. Сценарий
настоящей DEMO-лампы требует FastAPI, а статический HTTP-сервер обслуживал
только файлы. Финальный прогон выполнен на отдельном FastAPI-профиле,
DEMO-тест отправлял настоящий запрос, а тесты готового UI получили явную
фикстуру завершённой настройки. Продуктовый тест чистого мастера сохранён.

Новых подтверждённых P0 в выполненных сценариях нет. Контроллер доступа,
разрешения, формат файла подтверждения и команды Windows не ослаблялись.

DOM и синтаксическая проверка JavaScript завершились с кодом 0.
Основной Python 3.14 не содержит PySide6, поэтому тесты оболочки запущены
отдельно в релизном Python 3.11. Второй пропуск связан с тем, что том не
выдаёт короткое имя 8.3 для тестового файла.

Корпус `tests/test_rc3_bug_bash.py` содержит 96 уникальных русских фраз.
До исправлений были проверены 93 фразы, 80 прошли и 13 обнаружили сбой.
Три отрицательных варианта добавлены после исправления разбора кавычек.
Корпус выполняет реальный файловый адаптер и использует отдельную политику;
Ollama-планировщик недоступен в фикстуре, а окна приложений подменены.
Этот корпус проверяет маршрутизацию, а не качество пересказа и не запуск Windows.

Отдельный нативный прогон использует текущие исходники, PySide6/Qt WebEngine
из проверенной сборки, временные папки и реальный localhost Ollama. Все
удаления ограничены одноразовым тестовым файлом в разрешённой папке.
Журнал `report.json` в `.test-artifacts/bash-native-*/` фиксирует фразу,
ожидание, `action_results`, видимый ответ и время. При сбое сохраняется PNG
только окна QA и состояние интерфейса. Эти локальные файлы могут содержать
заголовки Windows-окон и не входят в Git.
