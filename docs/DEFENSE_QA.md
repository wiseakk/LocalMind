# Вопросы для инженерной защиты

Ответы описывают этот checkout. Реальные результаты испытаний надо показывать
по протоколу, не подменяя их mock-тестами или историческими рассказами.

1. **Какую задачу решает проект?** Компьютер принимает русскую речь и текст,
   отвечает локальной моделью и выполняет ограниченные разрешённые действия.
   Цель — удобство, объяснимое управление и проверяемая безопасность.
2. **Почему локальная архитектура?** Аудио и вопросы не нужно отправлять
   облачному сервису; после загрузки ресурсов возможен offline inference.
   Цена — требования к памяти и производительности компьютера.
3. **Что делает сервер, а что браузер?** Браузер записывает, показывает и
   воспроизводит; Python проверяет полномочия и вызывает локальные компоненты.
   Поэтому обход интерфейса не должен обходить серверную проверку.
4. **Что такое STT?** Это преобразование звукового сигнала в текст.
   faster-whisper использует нейросетевую модель; она может ошибаться в именах.
5. **Зачем черновик распознанной речи?** Ошибка STT не должна запускать программу
   автоматически. Пользователь видит исходную расшифровку и исправляет её перед отправкой.
6. **Почему нельзя исправлять речь незаметно?** Тогда пользователь не сможет
   отличить свои слова от догадки системы. Подсказка словаря допустима, но итоговый
   текст всё равно должен быть показан и проверен человеком.
7. **Что такое VAD?** Voice Activity Detection выделяет участки с речью.
   Это уменьшает обработку пауз, но не гарантирует верного распознавания.
8. **Какие профили STT есть?** base/int8/CPU, small/int8/CPU и medium/float16/CUDA.
   Все многоязычные, язык выбран русский. Лучший профиль устанавливают экспериментом.
9. **Зачем CPU fallback?** CUDA может отсутствовать или не хватит VRAM.
   GPU-профиль повторяется на CPU, возвращая явный признак fallback; скорость не обещается.
10. **Почему сохраняется версия PyAV?** `av==18.1.0` закрепляет совместимость
    декодера, которая уже требовалась проекту. Смена версии требует отдельной проверки.
11. **Как ограничивается длинная запись?** Максимум 30 секунд и 8 МБ;
    декодирование ограничено числом отсчётов и временем, весь native worker — 120 секундами.
12. **Почему дочерний процесс, а не только таймаут потока?** Таймаут ожидания
    Python-потока не останавливает зависший native inference. Процесс можно завершить
    и освободить ресурсы; недостаток — повторная загрузка модели на запрос.
13. **Что такое TTS?** Преобразование текста в звук. Piper с локальным русским
    голосом создаёт WAV; браузер воспроизводит, останавливает или отключает озвучивание.
14. **Почему не браузерный speechSynthesis?** Некоторые голоса используют облако.
    Это несовместимо с гарантией локальной обработки; отсутствующий Piper даёт инструкцию установки.
15. **Какие лицензии у голоса?** Piper GPL-3.0; репозиторий моделей помечен MIT,
    карточка Denis указывает CC0 для датасета. Это разные объекты лицензирования.
16. **Что такое LLM?** Модель предсказывает продолжение текста по контексту.
    Она полезна для объяснений, но может уверенно ошибаться, поэтому ей не доверяют исполнение команд.
17. **Исполняет ли LLM команды Windows?** Нет. Намерение проверяют правила и
    адаптеры; обе генерации Ollama получают пустой набор инструментов. Текст модели
    не передают shell, eval или командной строке.
18. **Зачем разделять действие и ответ?** Сначала нужен фактический результат,
    потом его формулировка. Сбой генерации не должен отменять факт действия или запускать его второй раз.
19. **Что содержит ActionResult?** Успех, действие, цель, статус исполнения,
    наблюдаемое состояние, ошибка, режим и длительность. Эти поля отделяют проверяемые
    факты от разговорного комментария.
20. **Создан процесс — значит окно открыто?** Нет. Процесс может завершиться,
    перенаправить запуск существующему экземпляру или не показать окно. Статус прямо
    сообщает, что состояние окна не наблюдалось.
21. **Принята команда лампе — значит она горит?** Нет. Сетевой API мог принять
    запрос, а устройство остаться недоступным. Для утверждения о свете нужна отдельная обратная связь.
22. **Как проверяется комментарий LLM?** Composer возвращает JSON с копиями
    ключевых фактов и текстом. Несовпадения и ряд ложных утверждений отбрасываются.
    Это полезная защита, но не формальное доказательство смысла любого русского текста.
23. **Что увидит пользователь при отказе Ollama?** Правдивый статус уже показан,
    а комментарий заменяется безопасным fallback. Повторно обращаться к адаптеру ради ответа не требуется.
24. **Как избегается двойное действие?** `request_id` и отпечаток запроса
    регистрируются под блокировкой до запуска обработчика. Повтор ждёт те же Future-результаты.
25. **Гарантия дедупликации вечная?** Нет: память одного процесса, до пяти минут
    после завершения, максимум 128 записей. После перезапуска или истечения срока
    слепо повторять команду нельзя; сначала нужно проверить состояние.
26. **Почему цитата не исполняется?** В «расскажи про “открой блокнот”» команда
    является предметом разговора. Централизованные правила отбрасывают цитаты,
    отрицания и неоднозначный контекст до обращения к адаптеру.
27. **Что происходит с несколькими командами в одной фразе?** Система просит
    уточнить одно действие и цель. Это ограничение языка управления ради проверяемости.
28. **Откуда каталог приложений?** Из ярлыков Start Menu/Desktop и App Paths.
    Это обнаружение метаданных, а не доказательство безопасности всех найденных программ.
29. **Почему нельзя запускать путь из текста пользователя?** Такой путь мог бы
    вести к скрипту, оболочке или чужому файлу. API принимает только проверяемую цель
    из серверного каталога, а не произвольную строку команд.
30. **Зачем отпечаток разрешения?** Одно имя ярлыка можно сохранить при подмене
    executable. Разрешение связано с источником, путём и SHA-256 содержимого; после
    изменения пользователь должен выбрать цель заново.
31. **Что делать с двумя одинаковыми названиями?** Попросить выбрать точную
    запись каталога. Автоматически угадывать и запускать первый вариант опасно.
32. **Почему не закрывается Блокнот?** Нельзя гарантировать, что выбрано именно
    созданное ассистентом окно и что текст сохранён. Ручное закрытие сохраняет штатный
    диалог сохранения; массовое принудительное завершение не реализовано.
33. **Как защищён HTTP API?** Loopback bind и проверка реального адреса клиента,
    Host/Origin, запрет cross-site, ограничения размера и необязательный ключ.
    Это локальная граница; полноценного защищённого LAN-сопряжения пока нет.
34. **Почему опасно доверять X-Forwarded-For?** Злоумышленник может прислать этот
    заголовок сам. Запуск отключает доверие proxy-заголовкам; middleware проверяет реального peer.
35. **Как предотвращается XSS в ответах?** Markdown проходит DOMPurify,
    опасные элементы и внешние медиа запрещены, KaTeX работает с `trust:false`.
    CSP ограничивает загрузки; при сбое рендера остаётся текст.
36. **Как трактуются доллары в формулах?** Формулы задаются через `\(...\)`,
    `\[...\]` или `$$...$$`. Одинарные доллары оставлены обычным текстом, чтобы цены
    не превращались в неожиданную математическую разметку.
37. **Как измерить качество STT?** По записям с согласованными эталонами:
    WER — ошибки редактирования по словам, CER — по символам. Нужны число записей,
    условия и нормализация, а не один удачный пример.
38. **Чем тест с mock отличается от реального опыта?** Mock проверяет реакцию
    кода на заданный ответ. Он не доказывает слышимость микрофона, качество голоса,
    правильность модели или реальную реакцию устройства.
39. **Почему измеряются action_ms и llm_ms отдельно?** Быстрое действие может
    сопровождаться медленным текстом. Раздельные времена показывают источник задержки;
    потоковый статус делает эту разницу понятной пользователю.
40. **Каков личный вклад учеников при использовании AI?** Его нужно подтвердить
    объяснением кода, принятых решений, собственных тестов и опытов. Помощь AI
    раскрывается; неподтверждённые измерения и авторство не приписываются себе.
41. **Чем выбранная модель отличается от фактической?** Серверный выбор задаёт
    следующий обычный запрос. Фактическое имя берётся из ответа Ollama и может
    отличаться при alias/override. Ответ правил вообще не использует LLM.
42. **Почему после неудачной смены остаётся старая модель?** Сначала проверяются
    tags/show, локальность и короткая генерация. Только успешная проверка приводит
    к атомарной записи отдельного файла; `.env` не меняется.
43. **Откуда берётся tokens/sec?** eval_count × 10⁹ / eval_duration, поскольку
    Ollama возвращает наносекунды. При отсутствии/нуле duration скорость неизвестна.
    Загрузка, полное время Ollama и задержка приложения — разные измерения.
44. **Доказывает ли свободная VRAM GPU inference?** Нет. Placement берётся из
    `/api/ps` и сопоставляется с `ollama ps`. NVML показывает всё устройство,
    включая ASR, браузер и другие workloads; это не память одной LLM.
45. **Почему GGUF может быть несовместим?** Нужны поддерживаемые архитектура и
    версия runtime, шаблон и корректный вариант. Shards и vision projector требуют
    отдельной поддержки. До проверки установленного артефакта это оценка.
46. **Как предотвращён произвольный импорт?** Backend проверяет repository ID,
    источник и allowlist quantization, строит только разрешённый Ollama reference.
    Браузер не передаёт URL, Modelfile или путь; scripts репозитория не исполняются.
47. **Почему свободное место иногда неизвестно?** Ollama — отдельный daemon с
    собственным хранилищем, возможно другого пользователя. Диск проекта не доказывает
    место для моделей. Оператор должен подтвердить фактическое хранилище.
48. **Что означает «отменить поток»?** LocalMind закрывает HTTP pull. Если daemon
    делит загрузку с другим клиентом, она может продолжаться. Без реального наблюдения
    остановки приложение не утверждает, что сетевой transfer прекратился.
49. **Что доказывают оценки локального теста?** Только прохождение опубликованных
    точных проверок малого фиксированного набора с конкретным hash/settings/digest.
    JSON schema помогает формату, AST сравнивает код без исполнения. Это не общая
    точность, не качество русского языка во всех темах и не гарантия безопасности.
50. **Как сравниваются две модели честно?** Используются одинаковые задания,
    system prompt, assistant prefill, seed, контекст, бюджет и режим reasoning.
    Записываются реальные имя, digest, quant и placement. Неполный прогон не даёт
    полного сравнения; разные CPU/GPU placement мешают прямому выводу по скорости.
    Ручной пользовательский рейтинг хранится отдельно от автоматических checks.
